# 수업꾸러미 개선안 — 시트 발행에서 Claude 운영으로

> 작성 2026-10-02 · 상태: **1단계 운영 전환 구현(브랜치 `content-yaml`, 미리보기 확인 전)** — 결과 §5-1, 다음은 2단계 첫 실전
> 요청: "구글 시트 기반이라 수정 과정이 번거롭다. 협업용 시트를 Claude로 넘겨 사이트를 운영하는 방식으로 하고 싶다."
> 함께 볼 것: 수업나래 쪽 연계 검토 `dge-narae/docs/research/REAL-LIFE-CONTEXT-MATERIALS-NOTES.md`(데이터 결함·출처 분석의 출처)

## 0. 요약

- **정본을 구글 시트에서 저장소로 옮긴다.** 꾸러미마다 파일 하나(`content/kits/<id>.yaml`)를 두고, Claude가 읽고 고치고 검증하고 발행한다.
- **구글 시트는 "입력 양식"으로만 남긴다.** 협업자는 지금처럼 시트에 쓰고, Claude가 그 시트를 받아 꾸러미 파일로 옮긴다. 현재 내용을 시트로 내보낼 수 있어서, 고치는 작업도 "내보낸 시트에 표시 → 돌려받기 → 바뀐 칸만 반영"으로 왕복한다.
- **사람 손 대신 검증이 지킨다.** 발행 전에 `npm run check`가 스키마, 성취기준 원문, 단원↔영상 정합, 영상 상태, 퀴즈를 검사한다. 지금 사이트에 올라가 있는 5학년 1학기 영상 밀림 같은 오류를 발행 전에 잡는다.
- **발행은 미리보기 주소 → 운영자 확인 → 운영 반영** 순서다. GAS 발행 버튼, 붙여넣기용 엑셀, 시트 스크립트 속성의 GitHub 토큰은 은퇴한다.
- 서비스 쪽 개선(§4)은 전환 뒤에 이어 간다. 출처 표시, 신고 단추, 쓰임 표지 정리, 그리고 수업나래 연계용 공개 카탈로그·모음 화면·기사 유형이다.

## 1. 지금 흐름과 번거로운 곳

```
협업자 시트(작업자·교과마다, 열 구조 다름)
  → 붙여넣기용 엑셀 만들기(병합·ID 교정·개념 풀이·퀴즈 생성)            ← CONTENT_BATCH_GENERATION.md 283줄 절차
  → 원본 구글 시트에 붙여넣기(백업 → 필터 → 행 교체 → 행 수 확인)
  → [GitHub에 발행] 버튼(GAS) → data/raw/*.json 커밋
  → Cloudflare Pages 빌드(sheet-to-json.ts) → kit.dgedu.link
  (+ 꾸러미 추가·제목 변경 때 로컬에서 npm run og → 커밋을 따로)
  (+ 2개월마다 [영상 점검] → 결과는 시트 셀 색·메모에만)
```

| 번거로운 곳 | 근거 |
|---|---|
| **데이터가 네 번 옮겨지고, 열 구조가 세 가지다** | 협업 시트(에듀나비 도구의 ①단원·②콘텐츠 10열 등), 원본 시트(`kits`/`items`/`stage_meta`/`quiz`), 사이트 JSON. 매번 매핑 규칙과 ID 교정표(7건)를 다시 적용해야 한다 |
| **붙여넣기 오류가 사이트까지 간다** | 지금 라이브 데이터 기준이다(조사 2026-10-02).<br>· 5-1 꾸러미 4개 영상이 한 칸씩 밀렸다: `so5121` 기후 단원에 인구 영상, `so5122` 인구에 인권, `so5131` 인권에 헌법, `sc5111` 지층과 화석에 열.<br>· `so5232` 성취기준이 `[6사07-01]`로 잘못 들어갔다(`[6사06-02]`가 맞음).<br>· `so3111`·`so3112` 코드에 긴 줄표(`–`)가 들어갔다 |
| **빌드가 오류를 조용히 넘긴다** | `sheet-to-json.ts`는 잘못된 행을 "경고 후 건너뜀" 처리하고 배포를 계속한다(6/27 `6d586b4` 이후). 행이 빠져도 배포된다. 단원과 영상이 맞는지는 아무도 검사하지 않는다 |
| **따로 해야 하는 일이 잊힌다** | OG 카드는 빌드 환경에 폰트가 없어 로컬 `npm run og` + 커밋을 따로 해야 한다 |
| **영상 점검 결과가 시트에만 남는다** | 채널(출처) 정보도 기록되지 않는다. `video_license`는 1,479개 모두 빈칸이다 |
| **비밀 값이 시트에 있다** | `GITHUB_TOKEN`·`YT_API_KEY`가 스크립트 속성에 있고, 시트 편집 권한자는 볼 수 있다(SHEET_SETUP §6-1 주의) |
| **문서가 실제와 어긋났다** | README "현재 81 꾸러미(공개 59)" — 실제로는 81개 전부 공개다. CLAUDE.md "flow(용어 흐름형, 현재 전부)" — 실제로는 활동형이 22개다 |

## 3. 제안 운영 모델(C)

### 3-1. 흐름

```
협업자 ── 협업 시트(정해진 양식, 구글 시트·엑셀) ─┐
교사 ──── 설문(dgedu.link/kit-form)·신고 단추 ────┤
운영자 ── "so4122 3번 영상 바꿔 줘" ───────────────┘
                         ▼
               Claude(운영 세션, 런북 §3-6)
   읽기 → content/kits/*.yaml 수정 → npm run check → 변경 보고서
                         ▼ 운영자 확인
     작업 브랜치 push → Pages 미리보기 주소 → 확인 → main 병합 → kit.dgedu.link
```

- 원본 구글 시트와 GAS `발행`은 은퇴한다. 시트는 마지막 발행 상태로 읽기 전용 보관한다.
- 빌드(`sheet-to-json.ts` → 이름은 `build-content.ts` 등)는 `content/`를 읽는다. 결과물 `data/*.json`의 모양은 지금과 같아서 화면 코드는 그대로다.
- **전환이 안전한지 확인하는 방법**: 변환 직후 새 빌드의 `data/*.json`이 지금 것과 같은지 비교한다. 다른 곳이 0이어야 한다.

### 3-2. 꾸러미 파일 모양(초안)

```yaml
# content/kits/so4111.yaml
id: so4111
title: 1-1. 지도로 본 우리 지역
grade: 4
sem: 1학기
subject: 사회
unit: 1단원
unit_no: 1
flow: flow
sort_order: 1
published: true

intro:
  core_idea: 우리 지역을 나타내는 다양한 지도를 살펴보며 …
  core_question: 지도를 이용하면 우리 지역의 모습과 정보를 어떻게 파악할 수 있을까?
  concepts:                       # " ; " 짝 맞추기 대신 진짜 목록
    - term: 지도
      def: 우리가 사는 땅의 모습을 위에서 내려다본 것처럼 …
    - term: 방위
      def: 동, 서, 남, 북처럼 방향을 나타내는 것이에요. …
  standards:
    - code: "[4사05-01]"
      text: 우리 지역을 표현한 다양한 종류의 지도를 찾아보고, 지도의 요소를 이해한다.

stages:                           # stage_meta
  - name: 지도
    question: null

items:
  - key: v1
    stage: 지도
    use: 수업 전                  # 수업 전 · 수업 중 · 수업 후 · 배경지식
    url: https://www.youtube.com/watch?v=XXXXXXXXXXX
    title: …
    desc: …
    start: 0                      # 선택
    end: 95                       # 선택
    channel: YTN 사이언스         # 영상 점검이 채운다(사람이 쓰지 않음)
    status: ok                    # ok · 임베드차단 · 삭제·비공개 … (영상 점검이 채운다)

quiz:
  - q: 지도에서 기호의 뜻은 범례를 보면 알 수 있다.
    a: O
    explain: 범례는 지도에 쓰인 기호의 뜻을 모아 둔 표예요.
```

- **사람이 쓰는 칸과 기계가 채우는 칸을 나눈다.** `channel`·`status`·`content_count`는 기계가 채운다.
- 이미지·글 항목(`type: image`/`text`)과 앞으로 더할 기사 항목(§4 S7)은 같은 `items` 목록 안에 `type`만 달리 둔다.

### 3-3. 협업 시트 — "입력 양식"과 왕복

- **양식은 하나로 정한다.** 연구회가 이미 쓰는 에듀나비 도구 시트(`edu-kit-for-gas-edunavi`의 ①단원·②콘텐츠 열 구조)를 그대로 받는 쪽이 협업자에게 가장 부담이 적다.
  - 그 도구의 재생시간 자동 채우기·AI 초안·유튜브 주소 표준화도 그대로 쓸 수 있다.
  - `CONVERT_TO_EDU_KIT.md`의 매핑 규칙(단계 4개 대응, 탐구 질문 대표값 고르기, 아카이브 전용 콘텐츠 제외 보고)은 Claude가 매번 손으로 하지 않도록 **가져오기 스크립트로 굳힌다.**
- **새 단원 넣기**: 협업 시트 링크나 xlsx를 Claude에 준다. Claude가 가져오기 → 개념 풀이·OX 퀴즈 초안 생성(기존 규칙: 초등 눈높이, O/X 3:4 균형) → 검증 → 변경 보고서를 낸다.
- **기존 단원 고치기(왕복)**
  - `npm run export:sheet`로 지금 내용을 협업 양식 xlsx로 내보낸다. 숨긴 열 `kit_id`·`item_key`를 넣어 둔다.
  - 협업자는 그 파일에서 고치고, 지울 행은 `삭제` 열에 표시하고, 새 행은 키를 비워 둔다.
  - Claude가 돌려받은 파일과 내보낸 원본을 비교해 **바뀐 칸만** 반영한다. 행이 밀려도 키로 맞추므로 엉뚱한 단원에 들어가지 않는다.
- **단건 수정**: 운영자가 말로 요청하면 Claude가 해당 파일 한 곳을 고친다. 시트를 거치지 않는다.
- 시트 접근: Claude는 연결된 구글 드라이브로 시트를 직접 읽을 수 있다. 다만 지금 연결된 계정에서는 수업꾸러미 시트가 검색되지 않으므로, 그 계정에 공유하거나 xlsx로 내려받아 폴더에 둔다.

## 6. 운영자가 준비할 것
