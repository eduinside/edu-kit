# 협업 결과물 → 원본 시트 붙여넣기 파일 생성 가이드

여러 작업자가 작성한 협업 엑셀을 현재 운영 중인 Google Sheet 형식으로 합쳐, 검수 후 붙여넣을 수 있는 엑셀 파일을 만드는 절차이다.

이 문서는 **대량 병합 작업**을 위한 가이드이다. 편집자가 Google Sheet에 새 꾸러미를 직접 추가하는 일반적인 방법은 [SHEET_TEMPLATE.md](./SHEET_TEMPLATE.md)를 따른다.

## 1. 데이터 흐름과 작업 경계

운영 데이터의 흐름은 다음과 같다.

```text
원본 Google Sheet
  → 수업꾸러미 > GitHub에 발행(GAS)
  → data/raw/*.json
  → Cloudflare Pages 빌드
  → kit.dgedu.link
```

대량 병합 작업에서는 Google Sheet나 `data/raw/*.json`을 직접 수정하지 않는다. 먼저 **붙여넣기용 엑셀**을 만들고 검수한 뒤, 원본 Google Sheet의 해당 행을 교체한다.

## 2. 입력 자료의 우선순위

입력은 두 종류이다.

1. **현재 원본 시트의 내보내기 파일**
   - 기존 헤더, 현재 `kit_id`, 운영 중인 메타데이터와 단계 질문을 확인하는 기준이다.
   - Google Sheet에 접속할 수 없으면 최신 엑셀 내보내기를 사용한다.
2. **협업 작업 결과 파일**
   - `①단원별` 탭에서 단원 메타데이터와 성취기준을 읽는다.
   - 대상 콘텐츠 탭에서 영상 제목·URL·설명, 단계와 탐구 질문을 읽는다.
   - `읽어주세요` 같은 안내 탭을 제외하고 작업 대상 탭을 모두 확인한다.

동일한 교과·학기 자료에 원본 탭과 `수정본` 탭이 함께 있으면 **작업 요청에서 지정한 수정본만 정본으로 사용**한다. 두 탭을 섞으면 삭제되거나 수정된 영상이 되살아날 수 있다.

### 2026-06-04 협업본의 정본 탭

| 대상 | 사용할 탭 |
|---|---|
| 5학년 2학기 사회 | `②콘텐츠(5-2사회)` |
| 5학년 2학기 과학 | `②콘텐츠(5-2과학)수정본` |
| 6학년 2학기 사회 | `②콘텐츠(6-2사회)` |
| 6학년 2학기 과학 | `②콘텐츠(6-2과학)` |

5학년 2학기 과학의 `수정본`이 아닌 기존 탭은 사용하지 않는다.

## 3. 출력 파일의 범위와 탭

출력 파일에는 요청받은 학년·학기의 **붙여넣을 행만** 남긴다. 2026-06-04 협업본은 5학년 2학기와 6학년 2학기만 대상이다.

| 탭 | 역할 | 발행 여부 |
|---|---|---|
| `kits` | 꾸러미별 기본 정보 | 발행 |
| `items` | 단원 안내와 영상 콘텐츠 | 발행 |
| `stage_meta` | 단계 순서와 탐구 질문 | 발행 |
| `quiz` | 단원별 개념 확인 OX 문제 | 발행 |
| `concept_src` | 개념 설명 생성·검수용 보조 표 | 발행하지 않음 |

`gas/publish.gs`가 발행하는 탭은 `kits`, `items`, `stage_meta`, `quiz`이다. `concept_src`는 한 단원의 개념 설명을 한 셀에서 검수하기 위한 보조 탭이며, 실제 사이트에 쓰이는 값은 `items`의 `intro` 행에 있는 `concept_desc`이다.

## 4. `kit_id` 생성 규칙

이번 협업 자료의 의미형 ID는 아래 순서로 만든다.

```text
교과 접두사 + 학년 + 학기 + 대단원 + 소단원
```

- 사회: `so`
- 과학: `sc`
- 학기 숫자는 네 번째 문자이다.
- 제목이 `3-2.`이면 대단원 `3`, 소단원 `2`이다.
- 과학처럼 제목이 `2.`이고 소단원 번호가 없으면 소단원을 `1`로 둔다.

예:

| 대상 | 올바른 ID | 설명 |
|---|---|---|
| 5학년 2학기 사회 3-2 | `so5232` | `so` + `5` + `2` + `3` + `2` |
| 5학년 2학기 과학 2단원 | `sc5221` | `sc` + `5` + `2` + `2` + `1` |
| 6학년 2학기 과학 4단원 | `sc6241` | `sc` + `6` + `2` + `4` + `1` |

이 규칙은 이번 협업 자료의 기존 의미형 ID를 교정하기 위한 것이다. 일반적인 신규 꾸러미의 ID 자동 부여 방식은 [SHEET_TEMPLATE.md](./SHEET_TEMPLATE.md)의 `kits.id` 규칙을 따른다.

### 반드시 교정해야 하는 기존 오류

| 잘못된 ID | 교정 ID |
|---|---|
| `so5332` | `so5232` |
| `sc5212` | `sc5221` |
| `sc5213` | `sc5231` |
| `sc5214` | `sc5241` |
| `sc6212` | `sc6221` |
| `sc6213` | `sc6231` |
| `sc6214` | `sc6241` |

ID를 교정하면 `items`, `stage_meta`, `quiz`, `concept_src`의 `kit_id`도 함께 교정해야 한다. 이전 ID가 어느 탭에도 남아 있으면 안 된다.

## 5. 탭별 생성 방식

### 5.1 `kits`

- 협업본 `①단원별` 탭에서 학년, 학기, 교과와 제목을 읽어 같은 단원을 찾는다.
- 현재 원본 시트의 같은 단원 행을 기준으로 `unit`, `unit_no`, `sort_order` 등 운영 필드를 보존한다.
- 핵심 아이디어, 핵심 질문, 핵심 개념과 성취기준은 `kits`가 아니라 5.2절의 `items.intro`에 넣는다.
- `id`는 4장의 규칙으로 다시 계산한다.
- 이번 협업본처럼 `생각열기`·`탐구하기`·`확장하기` 단계로 구성된 자료는 `flow=activity`로 둔다.
- 출력 대상은 5학년 2학기와 6학년 2학기만 남긴다.
- 검수가 끝나 공개할 자료이면 `published=TRUE`로 둔다.

### 5.2 `items`

꾸러미마다 `intro` 1행을 먼저 만들고, 이어서 영상 행을 협업본 순서대로 만든다.

#### `intro` 행

| 필드 | 생성값 |
|---|---|
| `item_key` | `intro` |
| `stage` | `단원안내` |
| `type` | `intro` |
| `title` | 꾸러미 제목 |
| `sort_order` | `1` |
| `core_idea` | 협업본 핵심 아이디어 |
| `core_question` | 협업본 핵심 질문 |
| `concepts` | 중복을 제거하고 ` ; `로 연결 |
| `concept_desc` | 6장의 규칙으로 생성한 설명 |
| `standard_code` | 성취기준 코드를 원문 순서대로 ` ; `로 연결 |
| `standard_text` | 성취기준 본문을 같은 순서로 ` ; `로 연결 |

#### 영상 행

- 작업 탭에 나타난 행 순서를 유지한다.
- `item_key`는 꾸러미 안에서 `v01`, `v02`, … 순서로 만든다.
- `sort_order`는 `intro` 다음인 `2`부터 연속으로 부여한다.
- `stage`, 탐구 질문, 영상 제목, URL, 영상 설명은 협업본 값을 사용한다.
- 유튜브 URL은 실제 영상 ID 11자가 포함된 전체 URL인지 검사한다.
- 재생 구간 `분:초~분:초`는 `start_sec`, `end_sec`의 초 단위 숫자로 바꾼다.
- `분:초~끝`은 `start_sec`만 넣고 `end_sec`는 비운다.

### 5.3 `stage_meta`

활동형 꾸러미는 다음 순서를 사용한다.

1. `생각열기`
2. `탐구하기1`
3. `탐구하기2`
4. `확장하기`

단계 질문은 다음 순서로 결정한다.

1. 현재 원본 시트의 질문이 협업본에도 그대로 있으면 보존한다.
2. 그렇지 않으면 해당 단계의 콘텐츠 행에서 가장 많이 사용된 질문을 선택한다.
3. 동률이면 협업본에서 먼저 나온 질문을 선택한다.

`stage_meta`에 있는 단계명은 같은 꾸러미의 `items.stage`와 정확히 같아야 한다.

## 6. `concept_src`와 `concept_desc` 생성 규칙

`concept_src`는 다음 두 컬럼을 가진다.

```text
kit_id | concept_desc
```

한 꾸러미당 한 행을 만들고, `items.intro.concepts`의 각 개념에 대응하는 설명을 **같은 순서**로 ` ; ` 구분하여 넣는다.

```text
concepts     = 성질 ; 변화 ; 온도 ; 열의 이동
concept_desc = 물질이나 대상이 지닌 고유한 특징이다. ; 시간이 흐르면서 모습이나 성질 등이 달라지는 것이다. ; 물체의 따뜻하거나 차가운 정도를 수치로 나타낸 것이다. ; 열이 온도가 높은 곳에서 낮은 곳으로 옮겨 가는 현상이다.
```

작성 원칙:

- 초등학생이 이해할 수 있는 어휘로 쓴다.
- 개념마다 1~2문장으로 정의한다.
- 정의 안에는 구분자인 세미콜론을 쓰지 않는다.
- 용어 자체를 그대로 반복하는 순환 정의를 피한다.
- 역사·사회 개념은 시대와 맥락을 지나치게 단정하지 않는다.
- 과학 개념은 관찰 가능한 현상과 교과 수준의 인과관계로 설명한다.
- 같은 표기의 공통 개념은 가능한 한 같은 설명을 재사용한다.

생성한 `concept_src.concept_desc`는 같은 `kit_id`의 `items` `intro` 행 `concept_desc`에 그대로 복사한다. 두 값이 다르면 오류이다.

## 7. `quiz` 생성 규칙

각 꾸러미에 OX 문제 7개를 만든다. 이는 권장 범위인 5~8개 안에 있으며, 사이트는 이 중 2개를 무작위로 보여 준다.

| 필드 | 규칙 |
|---|---|
| `kit_id` | 해당 꾸러미 ID |
| `statement` | O/X로 명확히 판단할 수 있는 한 문장 |
| `answer` | 대문자 `O` 또는 `X` |
| `explain` | 정답의 이유나 틀린 부분을 바로잡는 짧은 설명 |
| `sort_order` | 단원 안에서 `1`~`7` |

내용은 해당 단원의 `core_idea`, `core_question`, `concepts`, `standard_text`와 영상 제목·설명 범위 안에서 만든다.

작성 원칙:

- 단원마다 `O` 3~4개, `X` 3~4개로 균형을 맞춘다.
- 사실 확인, 개념 관계, 자료 해석, 생활 적용을 고르게 포함한다.
- `항상`, `절대`, `전혀` 같은 표현은 실제로 틀림의 근거가 될 때만 사용한다.
- 관점에 따라 답이 달라지는 문장이나 조건이 빠진 문장은 만들지 않는다.
- 단순히 부정어 하나만 바꾼 비슷한 문항을 반복하지 않는다.
- `X` 해설은 틀렸다는 말로 끝내지 않고 올바른 사실을 제시한다.
- 다른 꾸러미와 문장이 완전히 중복되지 않게 한다.

## 8. 자동 검증 항목

엑셀을 내보내기 전에 다음 항목을 모두 검사한다.

### 범위와 행 수

- 요청받은 학년·학기 외의 행이 없는가?
- 꾸러미마다 `intro`가 정확히 1개인가?
- 영상 수가 협업본의 유효한 콘텐츠 행 수와 같은가?
- 각 꾸러미에 필요한 단계 행과 퀴즈 7행이 있는가?

### ID와 참조 무결성

- 모든 `kits.id`가 4장의 규칙과 일치하는가?
- 교정 전 ID가 어느 탭에도 남아 있지 않은가?
- `items`, `stage_meta`, `quiz`, `concept_src`의 모든 `kit_id`가 `kits.id`에 존재하는가?
- 같은 꾸러미 안에 중복 `item_key`가 없는가?

### 개념과 퀴즈

- `concepts`와 `concept_desc`의 조각 수가 같은가?
- 두 값의 순서가 개념과 정의의 순서로 정확히 대응하는가?
- `concept_src`와 `items.intro.concept_desc`가 완전히 같은가?
- 각 단원의 퀴즈가 7개이고 `sort_order`가 `1`~`7`인가?
- 정답이 `O`/`X`만 사용되었고 3:4 또는 4:3으로 구성되었는가?
- 중복 퀴즈 문장이 없는가?

### 파일 품질

- 수식 오류(`#REF!`, `#VALUE!`, `#N/A` 등)가 없는가?
- 필수 헤더의 이름과 순서가 원본 시트와 같은가?
- 긴 설명이 줄바꿈되고 헤더와 본문이 눈으로 읽을 수 있는가?
- 출력 파일을 다시 열어 실제 저장된 값으로 검증했는가?

### 2026-06-04 협업본의 기대 결과

| 탭 | 데이터 행 수 |
|---|---:|
| `kits` | 22 |
| `items` | 453 (`intro` 22 + `video` 431) |
| `stage_meta` | 88 |
| `quiz` | 154 (22단원 × 7문항) |
| `concept_src` | 22 |

이 행 수는 2026-06-04 협업본에만 적용한다. 입력 파일이 바뀌면 고정값으로 맞추지 말고 유효한 입력 행을 다시 세어 기대값을 갱신한다.

## 9. 원본 시트에 붙여넣는 순서

출력 파일을 기존 데이터 아래에 그대로 추가하면 같은 꾸러미가 중복될 수 있다. 먼저 원본 시트에서 대상 `kit_id`의 기존 행을 필터링하여 교체 범위를 확인한다.

권장 순서:

1. 원본 Google Sheet를 별도로 백업한다.
2. `kits`에서 대상 22개 ID의 기존 행을 새 행으로 교체한다.
3. `items`, `stage_meta`, `quiz`에서 같은 ID의 기존 행을 제거한 뒤 새 행을 붙여넣는다.
4. 관리용 `concept_src` 탭을 유지하는 시트라면 같은 방식으로 교체한다.
5. 탭별 행 수, ID, 필터 결과를 다시 확인한다.
6. 바로 발행하지 말고 표본 단원을 열어 제목, 영상 순서, 단계 질문, 개념 설명, OX 정답을 검수한다.
7. 검수가 끝나면 **수업꾸러미 > GitHub에 발행**을 실행한다.
8. Pages 빌드 로그와 실제 사이트에서 5학년·6학년 사회·과학 표본 단원을 확인한다.

원본 JSON을 로컬에서 직접 고치는 방식은 사용하지 않는다. 다음 빌드에서 시트 값으로 덮어써지며, 정본이 둘로 나뉘기 때문이다.
